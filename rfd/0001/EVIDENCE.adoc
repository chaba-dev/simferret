= RFD 1 Evidence

== Phase 0 — QEMU replay spike

The phase 0 spike is automated by
link:../../scripts/qemu-replay-smoke.sh[`scripts/qemu-replay-smoke.sh`]. The Nix
flake pins QEMU, a Linux kernel, a static C compiler, `cpio`, and `gzip`. The
script builds a diskless initramfs containing a single static `/init`, then
boots it under TCG with one vCPU and these replay-relevant settings:

[source,text]
----
-machine pc-i440fx-9.2,accel=tcg
-cpu qemu64 -smp 1 -m 128M
-nodefaults -no-user-config -display none -monitor none -serial stdio
-no-reboot -net none
-rtc base=2000-01-01T00:00:00,clock=vm
-kernel <pinned-bzImage> -initrd <generated-initramfs>
-append "console=ttyS0 quiet loglevel=0 panic=-1 nokaslr random.trust_cpu=off init=/init"
-icount shift=auto,rr=<record|replay>,rrfile=<replay.bin>
----

Run it with:

[source,shell]
----
.agents/dev ./scripts/qemu-replay-smoke.sh
----

The command records once, replays the same log twice, requires the guest marker
`SIMFERRET_PHASE0_OK version=1`, and compares all three serial streams byte for
byte. It writes executable versions, content digests, durations, serial output,
and QEMU diagnostics to a fresh `run.*` directory under
`.poc/qemu-replay-smoke/`; previous runs are preserved.

An x86-64 Linux run on 2026-09-05 passed with QEMU 11.1.0, Linux 6.18.49,
and machine type `pc-i440fx-9.2`. Record time was 6.02 seconds; the two replay
times were 10.07 and 10.02 seconds. The replay log was 6,211,724 bytes. The
recording and both replay serial streams had the same SHA-256 digest:

[source,text]
----
3771b23d96c0b8635c375ecb9e3c39664890e3dc7f5eb06a3317041799f25b66
----

The pinned kernel digest was
`d4c2d110cb9b82dad81517cc2f1f3a46d0e31c8937237cf3df59eeffb3d7070b`.
Two independent builds produced the same initramfs digest,
`9d8e70a63441ae9a752259bc6a34bddc502c3318b8868b923245b76748da2f33`.
The generated `evidence.txt` retains nanosecond durations and all artifact
digests for each invocation.

The runner fixes the build umask at `022` and regression tests verify identical
initramfs hashes when callers use umasks `022` and `077`. The tests also verify
that pre-existing output is preserved, mismatched replay bytes and missing guest
markers fail, and a QEMU process that ignores `SIGTERM` is forcibly terminated.
Timeout overrides must be finite and strictly positive; zero-valued overrides
are rejected before QEMU starts. The forced-termination regression separately
verifies that the runner returns status 137 before its outer watchdog expires.
Linux CI executes both these focused checks and the real QEMU record/replay
smoke test, retaining its diagnostics when a failure occurs.

No block, network, audio, graphics, monitor, host filesystem, or mutable image
device is present. This avoids the replay filters required by those device
classes. Serial output is supported by QEMU record/replay. The machine type is
explicit rather than using QEMU's moving `pc` alias.

This evidence establishes only that the pinned QEMU/kernel/initramfs tuple can
replay the fixed boot and guest action. It does not establish the RFD's later
process-control, semantic-event, assertion, or replay-identity acceptance
criteria.

== Phase 1 — Fixture and event protocol

The `simferret guest-agent` entry point reads commands from standard input and
writes structured events to standard output. Each frame is a four-byte,
unsigned, big-endian body length followed by UTF-8 JSON. Bodies are limited to
1 MiB. Every command and event envelope contains `protocol_version` (currently
`1`) and a stable command or event identifier; unsupported versions, malformed
JSON, unknown fields, truncated frames, and oversized frames fail the agent.
Request identifiers and payloads have a combined 64 KiB logical limit so every
accepted request and corresponding built-in fixture response can be represented
by an event frame.

Version 1 commands start and stop the echo-server process, make one workload
request, evaluate assertions, and shut down the agent. Events report server
lifecycle, every request attempt, matching responses or unavailability, the
complete assertion report, and agent shutdown. Requests and responses carry an
opaque request identifier and payload. The server's intentional corruption mode
changes only the returned payload so the safety checker observes the violation.
The agent retains the configured endpoint while the server is stopped, so an
outage command executes the real workload client and records its connection
failure. A private pipe reports server readiness only after the child process
successfully binds its socket.
Addresses are canonical numeric loopback socket addresses with nonzero ports;
invalid, hostname, wildcard, external, and ephemeral-port inputs are rejected
before a child starts. A controlled stop succeeds only when the agent terminates
a live child with `SIGKILL`, while cleanup tolerates an already-exited child.
The fixture also watches a private parent-owned standard-input pipe and exits if
the agent terminates before performing normal cleanup.

Normalized events retain the protocol version, stable identifiers, and complete
event body. Exactly three diagnostic fields are excluded as non-semantic:
`guest_pid`, `host_received_at_unix_nanos`, and `temporary_path`. Adding another
exclusion requires changing the typed normalizer rather than silently dropping
unknown JSON fields.

Run the phase checks with:

[source,shell]
----
.agents/dev cargo test --locked --workspace --all-targets --all-features
.agents/dev cargo clippy --locked --workspace --all-targets --all-features -- --deny warnings
----

On 2026-09-05, all twenty-two tests passed. Fifteen unit tests cover framing, protocol
version rejection, normalization, the TCP echo/corruption fixture, and all three
assertion forms. Seven process-level integration tests drive framed commands
through the real guest agent. The first starts the server, succeeds once, stops
the server, observes a stopped-phase attempt and bounded unavailable result,
restarts the server, and observes bounded matching success. The second corrupts
a response and verifies both a failed safety assertion and agent exit status
`1`. Additional regressions cover occupied and unusable server addresses, a real
stopped-phase client call, unexpected child death, request-size boundaries, and
bounded assertion-report serialization. Assertion details reference stable event
identifiers rather than copying arbitrary request data. Assertion bounds are
measured in stable event identifiers, not host time. Process tests concurrently
drain all pipes, enforce bounded waits, and verify that terminating an agent also
terminates its fixture child.
