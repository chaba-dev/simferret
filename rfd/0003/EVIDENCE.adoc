= RFD 3 Evidence

== Entry gate

The entry gate selects `poc/rfd3-workload/main.c` as the acceptance workload.
It is a bounded C program with no SimFerret library dependency. Its line protocol
can echo asymmetric input, create and detect invocation state under `/tmp`,
double-fork a session-leader descendant that ignores `SIGTERM` and retains
standard output, and fetch one bounded TFTP response from the existing
`10.0.2.2` RFD 2 peer. It recognizes `EACCES` from the peer-specific prohibited
route separately from malformed or unavailable responses. The `fetch` command
accepts the scenario's independently generated expected payload rather than
deriving it from the request identifier. These behaviors cover the process,
fresh-root, live-output, and network assertions required by the RFD without
putting application interpretation in the guest agent.

This selection does not claim that RFD 3 process supervision exists. Booting and
supervising the external executable remains the first Phase 0 task.

=== Representative artifact capture

The checked-in capture command is:

[source,shell]
----
.agents/dev ./scripts/rfd3-entry-gate.sh
----

It compiles the fixture as a static little-endian x86-64 Linux ELF and emits two
uncommitted inputs below one unique `.poc/rfd3-entry-gate/capture.*` directory:
the executable itself and a local OCI image layout containing that executable in

selected config, manifest, and layer blobs. The script uses canonical JSON,
USTAR metadata with zero timestamps, and a fixed entry order; it neither pulls

3.14.7 from the pinned development environment. Repeating the command into a

== Phase 0 workload and OCI spike

The Phase 0 spike answers the packaging questions before any typed
specification or assembler exists. It is throwaway prototype code under
`poc/rfd3-phase0/` driven by `scripts/rfd3-phase0-spike.sh`; the Phase 1 Rust
assembler replaces the prototype. The prototype deliberately reuses
standard-library primitives (`json`, `tarfile`, `gzip`, `hashlib`) rather than
hand-rolling container parsing, and it never extracts a layer with the host
`tar` program.

The checked-in command is:

[source,shell]
----
.agents/dev ./scripts/rfd3-phase0-spike.sh
----

It compiles one external static executable and one dynamically linked
executable from `poc/rfd3-workload/main.c`, builds four local OCI image
layouts, applies representative layers twice, normalizes every source into a
content-addressed store, removes the entire generated source tree, and only
then records and passively replays each workload through one guest supervisor.
The guest supervisor is a spike, not the Phase 2 agent: it launches the packaged
program in a private `chroot`, feeds it a fixed command file, drains its output
while it runs, and then kills and reaps every remaining guest process. It
exposes no command protocol, makes no application-protocol assertions, and does
not yet apply a normalized launch configuration.

Every workload printed the same bounded exchange, and both replays of each
source were byte-identical to its record:

[source,text]
----
ready version=1
echo value=asymmetric_42
state value=fresh
descendant state=escaped
stopped status=0
supervisor source=<source>
supervisor workload_status=0
supervisor cleanup_reaped=1
supervisor output_bytes=101
SIMFERRET_PHASE0_SUPERVISOR_OK version=1
----

`cleanup_reaped=1` is the escaped double-forked session leader the fixture
creates: it survives the primary process, retains the workload output
descriptor, and is killed and reaped only through the supervisor's
whole-guest barrier. The output stream reached end of file only after that
barrier, so no workload descriptor survived it.

=== Layer semantics and canonical identity

The layer-semantics layout applies a base layer and an upper layer that
exercise directory metadata updates, content and metadata replacement, a
whiteout that removes a lower entry with no same-layer addition, a whiteout
whose same-layer addition must survive, an opaque directory, a lower file
replaced by an opaque directory, new nested directories, a relative symbolic
link that escapes upward but stays inside the root, and a whiteout for a path
that does not exist. The `opt` opaque marker and the root-opacity marker both
appear *after* the additions they coexist with, so an implementation that
applied markers in archive order would delete same-layer additions and change
the result. The `etc/swap` marker deliberately precedes its addition, because
it also covers a lower file replaced by an opaque directory.

Applying it twice, in separate processes with different `PYTHONHASHSEED`
values, produced one canonical digest over 19 entries and byte-identical
materialized trees:

[source,text]
----
semantics_canonical_digest=38782e7c828a0eec4ac79dc20ab30bf6ab3c0b10c3048b15265db4b0d74e27f0
semantics_entries=19
semantics_expanded_bytes=70808
semantics_duration_ns=141189175
semantics_reapply_equal=true
----

The observed final tree confirms each rule: `etc/` moved from mode `0755` to
`0750`; `etc/config` was replaced by upper content with new metadata;
`etc/remove-me` is the upper addition at mode `0600`, so the whiteout removed
only the lower-layer entry; `etc/pure-delete` is absent, so a whiteout with no
same-layer addition removes its lower entry; `etc/swap` is a directory
containing `new`, so a lower file can be replaced by an opaque directory;
`opt/keep`, `opt/drop`, and `opt/nested` are gone while `opt/new` survives the
opaque marker that appears after it; `srv/opaque/lower` is untouched by an
unrelated opaque marker; and both symbolic links kept their exact targets.

The canonical digest also covers numeric ownership, which the host staging tree
cannot reproduce because the spike runs unprivileged. The fixture sets `etc/` to
canonical `2000:2000`; the materialized tree shows the host owner instead. That
distinction is why the regression test asserts mode and modification time and
not ownership, and it is why guest-visible nonzero ownership remains a Phase 2
assembler and Phase 4 verification concern. Symlink modes are normalized to
`0777` in the canonical model, because a Linux symbolic link has no settable
mode, so the identity never claims a mode the guest cannot have.

=== Root-level opacity

A separate two-layer layout covers the root directory, because a root-level
opaque marker in the main fixture would erase the executable. The base layer
holds `bin/simferret-workload-fixture`, `keep/lower`, `drop`, and `dir/child`;
the upper layer re-adds `bin`, `keep/upper`, and finally a root
`.wh..wh..opq`. The resulting tree is exactly the upper layer's own additions:

[source,text]
----
opacity_tree=./bin ./bin/simferret-workload-fixture ./keep ./keep/upper
----

That proves root opacity removes lower-layer descendants rather than nothing,
and that it leaves same-layer additions alone even though the marker is last.

=== Content-addressed closure and live-source removal

Each source produces one raw closure and one derived entry. Raw evidence is the
opened executable plus the canonical specification for a binary, and
`oci-layout`, `index.json`, the selected manifest, the config, and each stored
layer for OCI. The prototype re-derives the canonical tree from the raw objects
on every replay and refuses to proceed when a raw object is missing, corrupt, or
inconsistent with its recorded size and digest.

Replay also verifies more than the tree. The binary specification is re-parsed
from its verified raw object rather than read back from the closure record, so
editing the record cannot change the launch the store reproduces; the
re-derived launch, layer evidence, policy versions, and limits are each compared
against the closure; and the closure record is pinned by a digested lock, so
editing it is detected even when the edit is internally consistent. The lock
belongs in the run manifest in the Phase 1 assembler; the store-sidecar lock is
the prototype equivalent. It is a corruption detector, not an authentication
mechanism: replacing the raw objects, the closure, the sidecar, and the derived
lock consistently would produce another self-consistent recording, which is the
same limitation RFD 3 records for content digests generally.

| `escaping symbolic link target at 'b'`

| `whiteout marker '.wh.a' is not a basename`

The prototype also rejects FIFOs, sockets, sparse files, empty or malformed
digests, empty manifests, numeric metadata outside its serializable range, an
opaque marker whose parent is still a non-directory after the layer is applied,
and invalid launch fields such as non-numeric or root credentials, duplicate
environment names, non-absolute working directories, volumes, and stop signals.
Its limits are prototype-local policy: 64 MiB stored layer, 256 MiB expanded
layer, 16 MiB file, 4,096 entries, 16 layers, 1,024-byte path, 4,096-byte
symbolic link target, 40 symbolic link expansions, 64 raw closure objects, and
a 4 MiB bound on cache metadata files. Phase 1 replaces them with the limits the
RFD fixes. The cache bound matters because replay reads `closure.json`,
`tree.json`, and the derived lock through the same bounded beneath-root reader
as raw objects, and a materialized tree containing a special file is rejected
rather than read.

Two deviations from the RFD's stated profile are deliberate and recorded for
Phase 1. Python's `tarfile` consumes GNU `longname` and `longlink` records
transparently, so a layer using them is accepted even though the prototype
rejects PAX headers; detecting the physical extension records would mean
re-implementing tar parsing, which the RFD forbids. And descriptor `urls` and
embedded `data` are not yet rejected, because the prototype only ever opens
local `blobs/sha256/` paths; that is a Phase 1 rejection requirement, not a
safety gap, since nothing is fetched.

The derived entry is also shaped differently from the RFD: it contains
`tree.json`, the materialized tree, and a lock naming the closure, while the
RFD describes a derived entry that names its complete raw closure. The
relationship is recorded, but in the closure record rather than in the derived
entry, so Phase 1 should decide which direction the RFD intends.

=== Rust primitive selection

The Phase 1 assembler should select existing primitives before writing custom
format handling. The spike evaluated the pinned workspace dependencies and the
candidate crates:

[cols="1,1,3",options="header"]
|===
| Concern | Selection | Rationale

| JSON
| `serde` 1.0 and `serde_json` 1.0
| Already pinned in the workspace; serde's default of ignoring unknown fields
  matches the OCI forward-compatibility requirement without relaxing explicit
  rejection of unsupported selected values.

| Digests
| `sha2` 0.10
| Already pinned; supplies descriptor, DiffID, and canonical-identity SHA-256
  without a C dependency.

| Gzip
| `flate2` 1.1 with `rust_backend`
| Already pinned with the pure-Rust backend, so layer decompression is
  reproducible and does not link a system zlib. Decompression still needs an
  explicit expanded-byte bound because the reader can expand past a limit.

| Tar
| `tar` 0.4
| Streams USTAR/PAX entries without extracting them and exposes entry type,
  mode, ownership, link target, and size so the assembler can reject hard
  links, devices, sparse files, and setuid modes itself. The prototype's GNU
  longname experience is the reason to inspect physical extension records
  deliberately rather than rely on a library's convenience behavior.

| Safe filesystem access
| `rustix` 1.1
| Exposes `openat`-style calls with `O_NOFOLLOW`, `O_NONBLOCK`, and directory
  file descriptors so every source read and staging write stays beneath one
  opened root. `O_NONBLOCK` is required: a blocking open on a FIFO waits for a
  writer instead of rejecting the special file. `cap-std` 4.0 is the
  alternative but is a larger abstraction than this increment needs.

| OCI types
| Minimal `serde` structs, with `oci-spec` 0.10 as a reference
| The bounded profile needs strict rejection of unsupported selected values and
  deliberate ignoring of unrelated fields, which minimal structs express
  directly. `oci-spec` remains the reference for media-type and field naming.
|===

None of these crates is added to the workspace in Phase 0. The prototype is
Python so that a wrong policy costs a spike edit instead of an assembler
rewrite; Phase 1 adopts the selection above and its pinned versions.

=== Phase 0 regression tests

The focused command is:

[source,shell]
----
.agents/dev ./scripts/rfd3-phase0-spike-test.sh
----

It fakes the QEMU invocation and checks that one successful run records exactly
three QEMU invocations per source, removes the whole generated source tree, and
writes the expected evidence keys. The fake refuses to start while a `sources`
directory exists, so a regression that moved deletion after QEMU would fail
rather than pass. It fails divergent, incomplete, and infrastructure-failure
guest output, and it requires invalid duration bounds to fail before QEMU
starts.

It then exercises the prototype directly: the layer-semantics digest and tree
are stable and include a pure-deletion whiteout, an opaque directory after its
same-layer addition, and a file replaced by an opaque directory; root-level
opacity produces exactly the upper layer's additions; the binary and static OCI
sources converge; repeated layout generation is byte-stable; a missing, corrupt,
or tampered raw object, a tampered derived entry, an edited closure record, a
closure whose launch no longer matches its specification, a closure missing its
specification object, an oversized closure record, and a special file inside a
cached tree all fail materialization; a symbolic-link source is rejected; a
whiteout whose parent the same layer replaces with a symbolic link is accepted
while a marker inside a lower-layer symbolic link is refused; and every
unsupported construct is refused without partial output.

== Phase 1 typed specification and canonical assembler

Phase 1 replaces the Python prototype with `crates/simferret/src/workload/`: a
strict TOML specification, a bounded beneath-root reader, an OCI image-layout
normalizer, a canonical tree and identity, and a raw closure plus derived cache
store. It selects the Rust primitives the Phase 0 spike recommended: `serde` and
`serde_json` for JSON, `sha2` for digests, `flate2` with `rust_backend` for
gzip, `tar` 0.4 for layer records, and `rustix` 1.1 for `openat`-style access
with `O_NOFOLLOW`, `O_NONBLOCK`, and directory descriptors. The prototype is no
longer on any execution path.

=== Resolved Phase 0 deviations

* GNU `longname` and `longlink` records, PAX `x` and `g` records, hard links,
  devices, FIFOs, sockets, sparse files, setuid and setgid modes, and unknown
  tar type bytes are each rejected by inspecting the physical record type with
  raw iteration. The prototype accepted GNU long names because Python's
  `tarfile` resolved them transparently.
* Selected descriptors that declare `urls` or embedded `data` are rejected
  before the referenced content is opened. Unselected descriptors are still
  ignored whatever they contain, so forward compatibility is preserved.
* The derived entry names its complete raw closure. `derived/<canonical>/lock.json`
  records the closure digest, the canonical digest, and the tree and template
  digests, and verification refuses a derived entry that does not name the
  closure being replayed. The Phase 0 record-direction question is resolved in
  favor of the RFD's "each derived entry names its complete raw closure".

=== Bounded profile

The Phase 0 prototype's limits are adopted as fixed constants: 1 MiB
specification, layout, manifest, and config; 4 MiB index; 64 MiB stored layer;
256 MiB expanded layer and canonical expanded bytes; 16 MiB file; 4,096 entries
per layer; 16 layers; 1,024-byte path; 4,096-byte link target; 40 link
expansions; 64 raw closure objects; 32,768 canonical entries; 4 MiB cache
metadata; 256 arguments and environment entries; 4 KiB per argument and
environment entry; and 64 KiB total environment. Every bound is recorded in the
raw closure, so changing one changes the workload identity and a recording made
under other limits fails verification rather than being reinterpreted.

Two further profile decisions are recorded here. Modification times are limited
to the unsigned 32-bit whole-second range because the guest template is a `newc`
CPIO archive, and a timestamp the template cannot encode is rejected rather than
truncated. A standalone binary installs at the one fixed canonical path
`/bin/simferret-workload`; binary specifications therefore carry no install path
and no auxiliary file tree.

The Phase 1 store holds exactly one workload closure and refuses to replace it
with a different one, so the derived entry can name its closure unambiguously.
Reusing a shared store across different workloads is deferred to the Phase 3 run
integration, which will name closures by digest.
