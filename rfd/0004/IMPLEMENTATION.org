#+TITLE: RFD 0004 implementation checklist
#+STARTUP: showall

Implements [[file:README.adoc][RFD 4: Deterministic guest time model]].

* Objective

Remove host-dependent clock scaling and idle pacing from guest execution, make
the pinned model part of versioned VM identity, and state precisely what the
earlier increments did and did not establish about fresh executions.

* Entry gate
:PROPERTIES:
:STATUS: DONE
:END:

- [X] Measure guest time reproducibility under the current configuration and
  separate the time model's contribution from the result of fixed work.
- [X] Establish that fixed work produces the same result while its measured
  virtual duration varies, and that the guest instruction stream is not
  identical across runs.
- [X] Identify a configuration that is reproducible at no measured wall-clock
  cost.
- [X] Record what the earlier increments did and did not claim about replay and
  fresh execution.

* Phase 0 — Pin and validate the time model
:PROPERTIES:
:STATUS: TODO
:END:

- [ ] Select the pinned scale by the documented rule and record why that value
  was chosen over its neighbors.
- [ ] Set the validation deadline used to accept or reject a scale, and
  validate against the supported-host matrix named in the RFD.
- [ ] Require zero varying time measurements across at least five complete runs
  on every host in the supported matrix.
- [ ] Require guest measurements to be equal across supported hosts for
  identical artifacts and the same model, not merely stable within each host.
- [ ] Pass the pinned model from the product's record and replay launch paths
  rather than configuring it separately, and assert that the launched options
  match the recorded identity.
- [ ] Confirm that a run recorded under the pinned model replays twice with
  matching normalized events, assertions, and semantic outcome digest.
- [ ] Fail a host that cannot complete under the pinned model as an unsupported
  execution rather than falling back to another model.
- [ ] Run the time-model probe as a continuous-integration gate on x86-64
  Linux, requiring every requested run to complete and the verdict to be
  `reproducible` rather than merely invoking the diagnostic.
- [ ] Define and document the re-validation trigger for changes to the pinned
  QEMU or guest kernel.

* Phase 1 — Identity, rejection, and migration
:PROPERTIES:
:STATUS: TODO
:END:

- [ ] Add the pinned time model to typed VM identity rather than leaving it in
  the adapter's diagnostic fields.
- [ ] Reject a run whose manifest time model differs from the configured model
  before QEMU starts, naming the first incompatible field.
- [ ] Require a run recorded before the pinned model existed to name its
  environment or an explicit legacy profile, and never acquire the new model
  through a default.
- [ ] Keep host-only observations such as wall-clock duration out of identity.
- [ ] Cover the new identity field with a compatibility or tampering test.

* Phase 2 — Contract and documentation
:PROPERTIES:
:STATUS: TODO
:END:

- [ ] Document the pinned model, its idle-advancement semantics, and its wakeup
  behavior in the project README and the run manifest.
- [ ] Document that the chosen scale defines an artificial performance model, so
  timeout-sensitive results are conclusions about that model rather than
  predictions of production timing.
- [ ] Document the unresolved input-arrival gap: live host input has no
  deterministic position in guest virtual time, and deterministic ingress is
  separate work.
- [ ] Record that replay's contract is conditional on artifacts, scenario,
  executable, initial state, the specific log, and matching events and outcome
  digest, and that RFD 2 already scopes its determinism claim to passive
  replays.
- [ ] State explicitly that time, entropy, and ordering fault injection remain
  unimplemented and are not implied by this increment.
- [ ] Record the measurements and validation results in ~EVIDENCE.adoc~.

* Exit criteria

- [ ] The probe's four guest time measurements are identical across at least
  five complete independent runs on every host in the supported matrix, and
  equal across those hosts for identical artifacts and the same model.
- [ ] The pinned model is what the record and replay launch paths use, and it is
  part of versioned VM identity with mismatches rejected before launch.
- [ ] Older recordings cannot silently acquire the new model.
- [ ] The model's guarantees and its unresolved gaps are documented.
- [ ] This increment introduces no new time, entropy, ordering, or compatibility
  surface.
- [ ] The earlier increments' replay and determinism claims are unchanged and
  correctly scoped.
