#+TITLE: RFD 0002 implementation checklist
#+STARTUP: showall

Implements [[file:README.adoc][RFD 2: Minimal deterministic simulation proof of concept]].

* Objective

Prove exact record/replay of one bounded client/server execution with a
controlled server restart before expanding SimFerret's application or fault
surface.

* Delivery rules

Each phase records its commands and decisive output. A phase is complete only when
its automated checks pass from a clean checkout in the documented environment.
New platform features discovered during the PoC are deferred unless they are
required by an acceptance criterion in the RFD.

* Phase 0 — Manual QEMU replay spike
:PROPERTIES:
:STATUS: TODO
:END:

- [ ] Select and pin a QEMU version and minimal x86-64 Linux image.
- [ ] Boot the image under TCG with one vCPU and no uncontrolled network or
  mutable host mounts.
- [ ] Record and replay a fixed guest command using QEMU ~icount~ record/replay.
- [ ] Verify replay twice and record any unsupported machine or device options.
- [ ] Save exact commands, durations, versions, and output digests in an evidence
  document beside this checklist.

* Phase 1 — Fixture and event protocol
:PROPERTIES:
:STATUS: TODO
:END:

- [ ] Implement the minimal echo server, workload client, checker, and guest
  agent.
- [ ] Define a versioned framed command and structured-event protocol for the
  controlled host/guest channel.
- [ ] Define explicit normalization rules for non-semantic event fields.
- [ ] Test safety, controlled-outage, and bounded-liveness assertion evaluation
  outside the VM.
- [ ] Require at least one request attempt while the server is stopped and a
  bounded failed or unavailable result.
- [ ] Add an intentional response-corruption mode that proves property failures
  propagate to a nonzero result.

* Phase 2 — Rust record path
:PROPERTIES:
:STATUS: TODO
:END:

- [ ] Parse the echo restart scenario and generate a stable choice plan from its
  seed.
- [ ] Launch QEMU in record mode and drive the finite scenario without wall-clock
  sleeps controlling semantic choices.
- [ ] Terminate and restart the server at an explicit recorded choice point.
- [ ] Persist the manifest, scenario, choice plan, replay log, normalized events,
  assertion results, semantic outcome digest, and diagnostic logs atomically
  under one run identifier.
- [ ] Print a replay command and return an exit status derived from assertions
  and infrastructure health.

* Phase 3 — Rust replay path
:PROPERTIES:
:STATUS: TODO
:END:

- [ ] Validate artifact digests and environment compatibility before replay.
- [ ] Launch QEMU from the recorded initial state in replay mode.
- [ ] Detect early termination, hangs, surplus events, missing events, and event
  divergence with an actionable first-difference report.
- [ ] Compare normalized event, assertion, and semantic outcome artifacts.
- [ ] Prove two consecutive replays produce byte-identical semantic artifacts.

* Phase 4 — Acceptance and evidence
:PROPERTIES:
:STATUS: TODO
:END:

- [ ] Automate the record-and-replay demonstration in a supported environment.
- [ ] Verify a different seed changes the materialized request or fault plan.
- [ ] Verify at least one request encounters the stopped server and reports a
  bounded failed or unavailable result.
- [ ] Verify artifact or replay-identity tampering is rejected.
- [ ] Verify intentional fixture corruption fails its safety assertion and CLI
  exit status.
- [ ] Record record/replay duration, artifact sizes, fidelity limitations, and
  all observed divergence in ~EVIDENCE.md~.
- [ ] Recommend one next increment without implementing it.

* Exit criteria

- [ ] Every acceptance criterion in the RFD has linked automated or captured
  evidence.
- [ ] The PoC can be demonstrated from a clean checkout without undocumented
  interactive setup.
