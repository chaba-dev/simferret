# SimFerret pinned time-model reference values (RFD 4 Phase 0).
#
# The guest measurements, the artifact identities, and the model below were
# produced by `scripts/time-model-probe.sh` under the pinned model on the
# reference x86-64 Linux host (AMD Ryzen 5 3600, 12 threads, Linux 6.18.41),
# with the pinned QEMU 11.1.0, the pinned guest kernel 6.18.49, and the
# initramfs the probe builds from `poc/time-model/probe.c`. The run, its
# deadline, and its reason are recorded in `rfd/0004/EVIDENCE.adoc`.
#
# `scripts/time-model-gate.sh` compares a host's validation run against these
# values. They are exact rather than tolerances: the RFD requires the guest
# measurements to be equal across the supported hosts for identical artifacts
# and the same model, so a host that produces different values fails instead of
# passing with a warning.
#
# The artifact identities are SHA-256 digests of the QEMU executable, the guest
# kernel, and the probe's initramfs. The QEMU digest is the pinned emulator the
# flake builds, which carries `poc/time-model/qemu-nosleep-replay-flush.patch`;
# re-measuring the pinned model against it reproduced every value below, so the
# patch does not move the guest's measurements. The QEMU digest rather than only its version
# string is what makes a rebuilt or patched QEMU visible: a binary with an
# unchanged version string would otherwise pass silently.
#
# Re-validation trigger: any change to the pinned QEMU or guest kernel (in
# practice a `flake.lock` update that moves either), to the model in
# `crates/simferret/src/vm.rs`, or to the probe source makes these values stale.
# Re-measure on the reference host, re-record them here and in
# `rfd/0004/EVIDENCE.adoc`, and let the gate re-validate every host in the
# supported matrix. Until then the gate fails, which is the intended outcome: a
# host that cannot complete under the pinned model is an unsupported execution
# rather than a reason to fall back to another model.
